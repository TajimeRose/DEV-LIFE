## 1. ปัญหาอัตลักษณ์แบรนด์ (ลำดับความสำคัญสูงสุด)

เดิม DEV-LIFE มีลุค "สีเขียวเข้มธรรมชาติ + วัสดุออแกนิก" ชัดเจนแต่ถูกเปลี่ยนเป็น
"slate/blue แบบ Linear-Vercel ทั่วไป" หมด

### 1.1 Sidebar สูญเสียตัวตน (ต้องแก้)
- **เดิม:** พื้นหลัง `#14231c` (เขียวเข้ม) กับ text `#d7e2dc` + เน้น accent เขียว `#4ec38a`
- **ใหม่:** เปลี่ยนเป็นสีพื้นปกติ slate แล้วเน้นน้ำเงิน `#2563eb`
- **ปัญหา:** sidebar เป็นองค์ประกอบที่เห็นตลอดทั้ง app แต่ตอนนี้กลายเป็น "แถบข้างสีเทา
  ทั่วไป" ที่แยกไม่ออกว่าเป็นของ DEV-LIFE
- **แนวทาง:** คงสีหม่น ๆ เดิม (แต่ปรับค่าให้เข้ากับโทเค็นใหม่) หรือจับเอาเนื้อสัมผัสเดิม
  มาไว้ — อย่างน้อยคง accent สีเขียวของแบรนด์ไว้เป็นประจำตัว

### 1.2 หน้าล็อกอิน/สมัคร (Auth) รื้อทิ้งจนเผือก
- **เดิม:** `auth-story` เป็น gradient เขียวเข้ม + dot pattern + preview สวย ๆ สื่อถึง
  "ความเป็น workspace ที่อบอุ่น"
- **ใหม่:** เปลี่ยนเป็น `surface-2` เรียบ ๆ + ลายจุดสีเทาจาง
- **ปัญหา:** หน้านี้คือสิ่งที่คนเห็นเป็น **แรกสุด** แต่กลับกลายเป็นด้านเรียบ ๆ ที่generic
- **แนวทาง:** คืน gradient/แบรนด์เขียวให้ `auth-story` (อนุญาตให้ใช้สีเข้มกว่าโทเค็น
  ปกติได้ในแค่ point นี้) หรือออกแบบ visual แบบใหม่ที่ยังสื่อตัวตน

### 1.3 โทนสีหลักเปลี่ยนจนแยกไม่ออก
- brand เปลี่ยนจากเขียวเป็นน้ำเงิน `#2563eb` ทั้งระบบ
- ถ้าเปลี่ยนสีนี้เป็นตั้งใจ ควรทำเป็น deliberate decision และปรับ icon/logo ร่วมด้วย
  ไม่ใช่แค่ CSS — ขอให้ยืนยันก่อนลงมือ
- **ข้อเสนอ:** ถ้าอยากได้ลุค "pro/precision" ที่ยังมีตัวตน ลอง `brand = เขียวเขียวน้ำเงิน`
  (teal-green) แทน pure blue เพื่อให้สะพานกับลุคเดิม

## 2. ลำดับชั้นข้อมูล (Density / Hierarchy)

แอปสาย "developer workspace" ควรแน่นและอ่านง่าย แต่การเปลี่ยนนี้ทำให้ข้อมูลกระจาย/
จางลง

- ตัวเลข stats: `28px` → `26px`, `font-weight 700→750` (ดูกระจุก)
- padding/font ทั่วทั้งหดเล็กลง + ช่องไฟกว้างขึ้น ข้อมูลดูเบาบาง
- **แนวทาง:** เพิ่มความหนาแน่นกลับในมุมมองข้อมูล (board, stats, task list) — อย่าใช้
  spacing แบบ marketing page มาใช้กับ data workspace

---

## 3. จุดดีที่ควรเก็บไว้ (อย่าไปแก้ทิ้ง)

- การ์ด Kanban มี accent สีต่อการ์ด (`--card-accent`) + hover lift + drag state — ดี
- dark mode ผ่าน `prefers-color-scheme` + `data-theme` สมบูรณ์ — ดี เก็บไว้
- transition นุ่ม ๆ บน interactive elements — ดี
- design tokens + radius/shadow ไล่ระดับชัดเจน — ดีมาก เก็บระบบนี้ไว้

## 4. ประเด็นเชิงเทคนิคที่ต้องแก้ก่อน merge

### 4.1 CSS modal ถูกย้าย แต่ test ยังผูกกับ globals.css (สำคัญ)
- Test `src/lib/github/timeline-view.test.ts` (บรรทัด 38-43) อ่าน `globals.css` เพื่อเช็ค
  regex ของ `.ui-modal`, `.ui-modal-body`, `.ui-modal-layer`
- แต่ CSS modal จริงถูกย้ายไปอยู่ `swiss.css` แล้ว — `globals.css` เหลือแค่ "stub" ไว้
  ให้เทสผ่าน
- **อันตราย:** ถ้าอนาคตมีคนลบ stub เหล่านี้ เทสจะเด้งทันที
- **แนวทาง:** ย้าย test ไปอ่านจาก `swiss.css` แทน (ไฟล์ที่มี CSS จริง) แล้วลบ stub ใน
  `globals.css` เพื่อหลีกเลี่ยงโค้ดซ้ำซ้อน

### 4.2 เอกภาพของ CSS (minor)
- มี class ซ้ำ/ทับซ้อนระหว่าง `globals.css` กับ `swiss.css` (เช่น `.ui-button`,
  `.ui-modal`, reset) ควรจัดให้อยู่ที่เดียว: `swiss.css` เป็น design system หลัก,
  `globals.css` เหลือแค่ reset + tailwind import
